# Bounded Shooter → Monium trace reconciliation

Validated in a five-row Nirvana Shooter audit; apply to similarly structured `agents.eval` outputs, not all exporters.

1. Resolve Shooter `output` result item's own `_id` via Nirvana content API. The content may be only `{cluster,table}`. Check YT `@row_count` and size before reading; parse `ya tool yt ... read-table --format json` as a stream of JSON objects with `JSONDecoder.raw_decode` rather than assuming JSONL. Extract `row_id`, `monium_trace_url`, `full_history`, and grade coverage in memory; do not persist prompts, answers, secrets, or raw trace spans.
2. If an authorized scoped Monium OAuth token exists, a working read-only request is `POST https://m.yandex-team.ru/api/gateway/root/tracing/getTrace`, JSON body `{"traceId":"<id>","organizationId":""}`, headers `Authorization: OAuth <token>` and `Content-Type: application/json`. Read the token inside the process; never print it or request/response payloads. Verify HTTP 200 for one trace, then retrieve exactly the row IDs in scope. If unauthorized, use the existing authorized-browser trace procedure; do not generalize one auth failure into absent telemetry.
3. In the response, `spans` have `name`, `status`, `durationUs`, `startTimeUs`, and a `labels` dictionary. Restrict extraction to span names, status/duration, `gen_ai.tool.name`, model name, and deliberately sanitized error fields. Do not persist `gen_ai.input.messages`, `gen_ai.output.messages`, tool call arguments/results, CSRF, headers, or cookies. Count logical tool calls from `full_history`; nested `execute_tool`, `run_tool`, and ATS spans may all represent the same call.
4. `full_history` calls are role=3 `tool_calls[].function.name`, results are role=4 matched by `tool_call_id`. Result data can be `content[0].text` as an object containing another `text` string; decode that JSON to obtain `result`. In a real trace, `skill_view` returned `{"result":"Cannot open skill '…': the skill could not be resolved."}` while the corresponding span had `UNSET_STATUS` and the trace had `errorsCount=0`.
5. Check the sequence per row: model route, requested skill, result, actual domain connector or isolated-child spans, next model turn, final answer. Repeated unresolved skill lookups with no connector call mean the response is unsourced for that domain even if Shooter `ok` and the final answer is nonempty. Do not infer the catalog/Registry root cause from the trace alone; inspect runtime bindings separately. Distinguish `run_agent:IronUserWorkflow` (wrapper) from a model invocation by IronUser.
6. Reconcile Shooter stats (`rows` may be `{total,ok,errored}`), YT unique row IDs, Monium links, and Grader rows. Null `grade_scores[metric].score` plus `score_status=error` is not a numerical failure score: report valid coverage and `N/A` for a missing task-success mean. A graph can fail due to other blocks even when Shooter and Grader execution states say success.

Privacy-safe report: per row, trace link, model-call count, tool family and number of failed skill resolves, connector evidence, final-answer presence, grading status. State separately what transport proves, what trace proves, and what still needs source/config investigation.
