# Staff read recovery acceptance

## Cause and change

The real Staff `person-full-info` request used `fields_to_return=login,name,department`. Its published contract permits `department_group`, not `department`. Atlas rejected the call locally, before native dispatch, but reported `Capability outside reviewed principal ceiling.` The model treated that input error as an upstream self-only access restriction.

The eight-line plugin change preserves admission, every allow/grant predicate, published schemas and native backend bytes. Reviewed service reads rejected locally now report a preflight input/contract failure and direct the model back to `service_catalog`. Invalid values are not rewritten or accepted. Broken pins/contracts remain blocked; genuine upstream ACL errors keep the existing backend path.

## Qualified evidence

- The unchanged eight-test cohort produced three expected diagnostic assertion failures with the original plugin and zero failures with the candidate.
- The same eight tests passed with the prepared Mac and Linux interpreters. All 38 owner/member allow/block decisions remained identical.
- Independent manifest-bound source review found no blocking findings. Identity is a fixture in these offline tests, not a genuine admission receipt.
- The portable cohort under `qualification/staff_read` retains the same test-class AST and passed all eight tests against the approved installation. It creates only an isolated scratch fixture.
- The exact candidate plugin was installed and independently read back on both hosts. Native required-policy readiness passed before activation; one QYP primary and one Mac Telegram edge resumed with the relay connected. No authentication or permission changes were made.
- In the existing private topic, a fresh authenticated owner request asked for the team using live Staff data. The real model again submitted the unsupported full-info field, received the new local diagnostic, then completed a valid `group-memberships` read with a narrower `person` projection.
- The final native result contained four records. The actual bot reply independently observed in the same topic included all four returned logins and identified the intended employee. This was a fresh read, not replay of a consumed input.

## Boundaries

This qualifies Staff team lookup and recovery from the local input error, not an employee-activity report or every read operation. The four records are the returned group-membership result; no wider upstream population is inferred from retained-output pagination. Genuine upstream ACL denial, a second employee and group admission were not exercised by this cohort.

The initial updater refused a stale edge PID before runtime changes. A later readiness observer used a JSON-only reader on valid native YAML after the files had been installed; activation remained blocked. The external continuation used the native safe YAML reader and completed only the remaining readiness/start phases without repeating pause or installation. Both failed receipts are retained in the private task evidence.
